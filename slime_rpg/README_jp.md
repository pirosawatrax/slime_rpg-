# Slime RPG - 「転生したらみんなスライムだった件」

霧のあるチャンク分割型ボクセルワールド、長押しによる採掘、橋、20スロットのインベントリ、セーブ／ロード、掘って入手し、持ち運び、食べることのできる鉱物、ターミナル風のスライムバトル、レベル、死亡、コマンド式の村、昼夜サイクル、そしてスライムキングを備えたゲーム。

設計書：`slime_rpg_design_v3.md`（第13節のステージ1～6。昼夜、ターミナル式の戦闘画面、1タイルの村は、この設計書の執筆後に決定された）。

## 起動方法

```
pip install -r requirements.txt
python main.py          # セーブデータがあれば続きから。なければ新しいランダムマップ
python main.py --new    # 新しいランダムマップで新規ゲーム。旧セーブは削除せず別の場所に退避
python main.py --seed N # 指定したシード値 N で新規ゲーム
```

Linux では、Ursina の読み込み前に `main.py` が `XMODIFIERS=@im=none` を設定する。これにより fcitx5／ibus がキーの離上イベントを取りこぼす問題を防ぐ（キーを離しても押しっぱなしになる、Space が反応しないなどの症状）。

この設定を無効にするには、次のように起動する。

```
SLIME_KEEP_IME=1 python main.py
```

## 村、スライムキング、ボス撃破後の世界（ステージ6）

### 村のコマンド

ターミナル風の画面で操作する。数字キーの1～9、0で選択するか、クリックして選ぶ。Esc で退出する。

画面を開いている間、ワールドは停止する。村で提供されるサービスは、シード値と村の情報によって決まるため、プレイヤーが変更した内容以外は保存する必要がない。

| コマンド           | 内容                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 宿屋（Inn）        | 色を問わず鉱物1個を支払って一泊する。所持している中で最も地味な色の鉱物から使われ、画面に対象が表示される。HPが全回復し、その宿屋が復活地点になる。夜に泊まると翌朝の07:12まで時間が進む。昼間に泊まった場合、時刻は変わらない。死亡すると最後に泊まった宿屋で復活する。一度も泊まっていなければ開始地点で復活する。 |
| 倉庫（Storage）    | 村ごとに20スロット。村同士で共有されない。アイテムのスタックを預けるには鉱物1個（色は問わず、地味な色から優先）を支払う。取り出しは無料。死亡しても中身は失われない。                                                                           |
| 取引（Trade）      | 商人が求める色の鉱物を、木材24個、岩石32個、またはレア鉱物1個と交換する。村ごとに求める色が異なるため、色によって価値が変わる。                                                                                             |
| 案内（Guide）      | 危険、色、鉱物、そしてスライムキングの居場所についてのヒントを得る。座標、方角、距離が示される。案内を受けるとHUDにもメッセージが表示される。                                                                                       |
| 依頼（Request）    | 村人が指定するレアカラーの鉱物を2個渡す。この村の倉庫のスロットが5個増える。1回限り。                                                                                                                   |
| サービス（Services） | ボス撃破後のみ利用可能。新しい色の鉱物を支払う。各村で1回限り。倉庫のスロットを10個増やすか、最大HPを恒久的に10増やす「活力のトニック」を購入できる。                                                                                 |

### スライムキング

スライムキングの巣は、ワールド最下部（Y座標1～8）にある17×17ブロックの部屋で、原点から数百ブロック離れている。

案内で教えてもらえるX座標とZ座標を頼りに掘り進み、中央の木材タイルに乗ると、戦闘するかどうかを尋ねる画面が表示される。

- レベル30のスライムで、能力値は固定。攻撃力は低く、防御力は意図的に高く設定されている。そのため通常のタックルだけでは弱く、相手の現在の色に勝てる鉱物を投げることが勝利の鍵となる。
- スライムキングは毎ラウンド色を変える。次の色は画面上部に色見本付きで表示される。 その前に鉱物を食べ、自分の色を変えて備えることもできる。色の変化量は常に90以上離れるように設定されている。
- 1回の攻撃でHPの20％を超えるダメージは与えられない。 そのため、レベルを上げて一撃で倒すことはできず、最低でも5回の攻撃が必要。逃走もできない。勝利時の経験値は通常の3倍。
- シミュレーションによるバランス調整（`BOSS_STAT_MULT`）：タックルだけで戦った場合、レベル25／30／35での勝率はそれぞれ約0％／36％／90％。相性のよい鉱物を投げ、回復のために鉱物を食べる戦術では、約69％／92％／96％。

### ボス撃破後の変化

ボスを倒すと、変更内容はすぐにセーブされる。

1. 通常の敵レベルに対する、ボスレベルの90％という上限がなくなる。
2. 新しい色が登場する。 各色チャンネルの範囲が60～200（512色）から40～220（10段階、合計1000色）に広がる。新しく生成されるチャンクの鉱石の約3分の1が新しい色になる。変更していないチャンクは直ちに再生成される。敵とスライムキング自身も、拡張された色の範囲を使う。
3. 村で前述のサービスを利用できるようになる。支払いには新しい色の鉱物を使う。

## 鉱石

鉱石は岩の表面にある9マスのうち1マス（`ORE_CELLS`）に表示される小さな点で、遠くからでも見えるような大きさではなくなった。

地下の鉱石は以前の約2倍に増えている。地表付近の岩石では約3.2％、深さ20ブロックより下では約4.1％の割合で鉱石が含まれる。つまり、深く掘るほど豊かになる。一方、地表の岩塊にはほとんど鉱石が含まれないため、地表に鉱石が大量に集まることはなくなった。

## 洞窟

洞窟は Minecraft に近い構造になっている。

- 曲がりくねったトンネルを生成する。2つのノイズ場がともに0.5付近の値を取る領域を利用する。
- より細かな第2の洞窟網と、大きな空洞も生成する。
- 地下の約13％を洞窟が占め、その大部分は互いにつながっている。
- 陸地の約3％の縦方向の区画に洞窟の入口が生成され、地表まで洞窟がつながる。木や岩塊は入口をふさがないように配置される。
- 湖底と最下部の3層は貫通せず、封じられたままになる。

調整項目は `config.py` の `CAVE_*` にある。

## 音楽

音楽はコードで作曲される（`audio/music.py`、`audio/director.py`）。起動時に約1秒かけて `assets/music/` に書き出される。

探索中は、72 BPMのゆったりしたハ長調ペンタトニックのベルメロディーを、パッド、ベース、柔らかなアルペジオが支える。戦闘中は、156 BPMの速いイ短調ペンタトニックのリフに、力強いベース、アルペジオ、ドラムが加わる。

- 起動するたびに異なる曲が流れる。 起動時にランダムなシード値で曲を新しく作曲する。さらに、その種類の曲を再生するたび、バックグラウンドスレッドで次の曲を作曲する。そのため、次の戦闘や次の探索区間では違う曲が流れる。起動後の最初の戦闘では、起動時に作られた曲が使われる。
- 無音やノイズへの対策。 Panda3D は1MBを超える音声ファイルをディスクからストリーミング再生する。フレーム処理が遅くなると、音が途切れたり、無音になったり、ノイズが発生することがある。`main.py` では `audio-preload-threshold` を設定し、曲全体をメモリに読み込ませるようにした。また、1.5秒ごとに再生中の曲が本当に鳴っているかを監視し、停止していれば再起動する。コンソールには `music: ... had stopped; restarting it` というメッセージが表示される。
- `SLIME_NO_MUSIC=1 python main.py` で音楽を無効化できる。音量は `MUSIC_VOLUME` で調整する。

## マップ

新しいゲームでは、ランダムなマップが生成される（`world/seeds.py`）。セーブ済みのゲームでは、そのマップが維持される。村、洞窟、プレイヤーが変更したブロックは、そのマップに属している。

ポーズメニューには New world（新しい世界） があり、実行前に確認が表示される。旧ゲームはセーブデータの隣にあるバックアップフォルダへ保存される。現在のシード値も表示される。

```
python main.py --seed 12345
```

このコマンドで、シード値12345の新しいマップを開始できる。既存のセーブデータはバックアップされる。

開始地点は原点に最も近い、開けた草地になる。木の中や穴の中に配置されることはない（`world/spawn.py`）。

戦闘画面と村の画面では、通常のHUD（インベントリ、ステータス、キー操作の説明、照準）が非表示になる。

ピクセルアートのスライムには、白目や口はなく、黒い点の目が2つ描かれている。

## ワールド、村、昼と夜（ステージ5）

### 水辺と地形

地形の特徴が小さくなるように調整された（`TERRAIN_SCALES`）。湖や川が狭くなり、水辺を横断する距離は90％が約40ブロック未満、99％が約70ブロック未満になる。橋を架けるには木材2～3スタック程度が必要となる。

広い海も存在するが、まれである。ジャンプで登れないほど急な斜面はない。

### 村

ワールドは128ブロック単位の地域に分割される。各地域はハッシュ値に基づき、約40％の確率で「村なし」となり、それ以外では緩やかで乾いた土地に村が1つ生成される。

この仕組みにより、同じシード値なら、村はチャンクやセーブデータをまたいでも同じ場所に生成され、村そのものを保存する必要がない。

村には建物がない。平らに整地された小さな土地の中央に木材タイルが1つあり、その隣に道標がある。道標は水ブロックで作られた柱、横木、先端で構成される。青色なので木と間違えにくく、水ブロックは掘り出せないため破壊もできない。

木材タイルに乗ると村のコマンド画面が開く。 HUDには最寄りの村と方角が表示される。木材タイル上では敵との遭遇が発生しないため、安全に利用できる。

### 昼と夜

1日は10分（`DAY_LENGTH`）。新しいゲームは朝から始まる。

- 変化するのは空の色だけ。 昼は水色、日の出・日没時はオレンジ、夜は濃い青になる。
- 遠景の霧も空と同じ色になり、地平線が自然につながる。プレイヤーの近くのものは昼間と同じ明るさを保つ。
- `NIGHT_WORLD_TINT` を有効にすると夜間にワールド全体を暗くできるが、デフォルトでは無効。
- 地下では変化しない。
- 夜間は敵との遭遇率が2倍になる。 ただし地表のみ。
- 時刻はセーブデータに保存される。

### 古いセーブデータについて

地形生成の仕様が変わったため、`WORLDGEN_VERSION` が6に更新された。古いセーブデータを読み込むと警告が表示される。その場合は `--new` で新しいゲームを始めることを推奨する。

古いセーブデータも読み込み可能で、フォーマット1の鉱物データはフォーマット2へ変換される。ただし、以前に変更したブロックの周辺では地形が変わって見える可能性がある。

## 戦闘（ステージ4、ステージ5からターミナル形式）

### 戦闘画面

黒い背景に緑色の文字を表示する。

各ラウンドは、タイプライターのように1行ずつ再生される。

```
> あなたのタックル！   （風切り音）
  スライムに12ダメージ。 （衝撃音）
```

続いて敵の行動も同様に表示される。レベルアップや戦闘結果は `*` で始まる行に表示される。

HPの数値は、その変化を引き起こしたメッセージが表示された時点で更新される。HPはバーではなく数値で表示され、双方のスライムのRGBカラーも表示される。

双方のスライムは、同じ32×32ピクセルのスライム画像を使い、それぞれの色で着色される（`game/sprites.py`）。Enterキーで文字送りをスキップできる。

### 敵との遭遇

地上を歩くと、歩数（移動したブロック数）がカウントされる。

安全な状態で12歩進んだ後、1歩ごとに3.5％の確率で戦闘が発生する。平均すると約40ブロック歩くごとに遭遇する計算になる。

木材の床や橋の上では歩数がカウントされず、敵とも遭遇しない。 採掘中や立ち止まっている間もカウントされない。

敵についての情報はセーブされない。敵は戦闘開始時に生成される。

### 敵のレベル

敵のレベルは主に地表からの深さに応じて上がり、1ブロック深くなるごとに0.5レベル上昇する。さらに、開始地点から遠くなるほど少しずつボーナスが加算されるが、最大でも+6。

最終ボスが登場するステージ6までは、通常の敵のレベルはボスレベルの90％（27）を超えない。

敵の色は60～200の範囲からランダムに選ばれる。能力値は同レベルの平均値の85％を基準に、±10％の変動がある。

### ラウンドと行動

プレイヤーが行動を選ぶと、素早さが高い側から行動する。同速の場合はプレイヤーが先に動く。

- タックル（Tackle）： ダメージは、対象の最大HPに対する一定割合を基準とする。攻撃力と防御力の比率、色の相性、運によって増減する。どのレベルでも戦闘が約5ラウンド続くように調整されている。敵のタックルも同じ計算式を使うため、敵から攻撃されたときも自分の色が重要になる。
- 投擲（Throw）： 選択中の鉱物を投げ、消費する。鉱物と敵の色の相性によってダメージが変わり、相性がよければ大ダメージ、悪ければ敵を回復させてしまう。投げる前に、選択中の鉱物の相性倍率が画面に表示される。
- 食べる（Eat）： 戦闘外と同じ効果で、選択中の鉱物を食べる。ただし、そのラウンドの行動を消費する。
- 逃走（Flee）： 同じ素早さなら成功率50％。素早さの優位が1ポイント増えるごとに成功率が3％上昇する（最低15％、最高95％）。失敗すると敵から攻撃を受ける。

戦闘中もマウスホイールまたは1～0キーで、選択中のインベントリスロットを変更できる。

### レベルアップ

獲得経験値は次の式で計算される。

経験値 = 6 × 敵のレベル × clamp（敵のレベル ÷ 自分のレベル、0.25～2）

レベルLからL+1へ上がるために必要な経験値は、8 × L²。

レベルアップごとに4～6ポイントの成長ポイントがランダムに配分され、HP、攻撃力、防御力、素早さが上がる。HPは最も選ばれやすい。成長ポイント1つにつき、HPは+4、それ以外の能力値は+1となる。

レベルが上がるほど必要経験値も増えるため、成長速度は徐々に遅くなる。レベル上限はない。

### 死亡

HPが0になると、持ち運んでいるアイテムをすべて失う。開始地点でHP全快の状態で復活し、ゲームは直ちにセーブされる。

レベル、経験値、色、ワールド、倉庫の中身は維持される。宿屋で復活地点を設定していれば、その宿屋で復活する。

鉱物を食べても、それが原因で死亡することはない。HPは最低1に保たれる。

戦闘中はEscキーが機能しない。戦闘中にウィンドウを閉じた場合、ダメージを受けた現在の状態がセーブされる。

## 鉱物（ステージ3）

### 色

各RGBチャンネルは8段階（60、80、…、200）で、合計512色。

スライムの初期色はグレー（130, 130, 130）。

### 鉱石の生成場所

岩石の約1.7％に鉱物が含まれる。鉱物が多い「鉱脈の豊富な区域」もある。

地表には小さな岩の露頭があり、その約30％に鉱石が含まれるため、掘る前に色を確認できる。鉱石が含まれるのは岩石のみ。

### 希少度

色の鮮やかさに応じて希少度が決まる。

- 地味な色：一般的。スタック上限32個、採掘時間約2.3秒。
- 鮮やかな色：希少。スタック上限16個、採掘時間約3.8秒。
- 珍しい色は地表から8ブロック下、レアカラーは20ブロック下から生成される。

鉱石を採掘すると、鉱物と岩石の両方を入手する。インベントリに空きが足りない場合、先に岩石が失われる。

### 鉱石の見た目

鉱石がある岩の面では、9マスのうち6マスが鉱物の色で表示される。遠くからでも色がわかるように、`ORE_GLOW` で明るくしている。

HUDには自分の色、色相、彩度が表示される。「Held」の色見本には、選択中の鉱物の実際の色が表示される。

### 食べる（E）

自分の色と鉱物の色のRGB距離が `EAT_SAFE_DISTANCE` 以内なら、最大HPの25％まで回復する。それを超える場合は、最大HPの15％までダメージを受ける。

どちらの場合も、自分の色は鉱物の色に向かって20％変化する。

ステージ5で死亡の仕組みが導入されるまでは、HPが1未満になることはない。

### 色の相性

`game/colors.py` に実装され、ステージ4の戦闘で使用される。

```
1 + 0.5 × sin（色相差）× 彩度係数
```

一方向に循環する3すくみの関係で、グレーは中立となる。攻撃側と防御側を入れ替えると、相性は反転する。

## セーブ

- 保存場所：`main.py` と同じ場所にある `saves/default/`。環境変数 `SLIME_SAVE_DIR` で変更可能。
- 保存される情報：ワールドのシード値、プレイヤーの位置と視点、インベントリ、選択中のスロット、復活地点、変更したすべてのブロック。
- Escメニューからセーブできる。`AUTOSAVE_SECONDS`（120秒）ごとの自動セーブ、「セーブして終了」を選んだとき、ウィンドウを閉じたときにも保存される。
- 「最後のセーブをロード」を選ぶと、ワールドは最後にセーブした時点へ戻る。それ以降の変更は失われる。
- ファンクションキーは使わないため、Ursina本体のショートカットと衝突しない。

### セーブ形式

`meta.json` と、編集されたチャンクごとの `chunks/c_<cx>_<cz>.json` で構成される。

生成済み地形との差分だけを保存するため、変更したチャンクのみが書き込まれる。ファイルは一時ファイルに書き込んでから、最終ファイル名に変更される。

`config.SAVE_VERSION` はセーブ形式のバージョンを表す。新しいバージョンで作成されたセーブは、変更せずに読み込みを拒否する。

セーブデータが破損していた場合は、`default.corrupt-<time>` という名前に変更して退避し、新しいワールドを開始する。

`config.WORLDGEN_VERSION` は地形生成方式の変更を示す。地形生成を変更するたびに値を更新する必要がある。古い差分データが新しい地形に適合しなくなる可能性があるため。

## テスト（Ursina 不要）

```
python -m unittest discover -s tests -t .     # Ursinaを使わない198件のテスト
python tests/smoke_stub.py                    # ダミーのUrsinaモジュールを使ってmain.pyのループを実行
```

## ファイル構成

```
main.py            Ursinaとの接続部分のみ：ウィンドウ、カメラ、HUD、チャンクのエンティティ、入力
config.py          調整可能な数値をすべて管理
strings.py         プレイヤー向けの英語メッセージをすべて管理
blocks.py          6種類のブロック：硬さ、スタック上限、音の種類、ドロップ、色
world/             ノイズ、地形生成、村（タイルと道標）、ボスの部屋、シード値、開始地点、ワールド、メッシュ生成、管理
save/              保存処理（ファイル、原子的書き込み、検証）、ゲーム状態とファイルの相互変換
items.py           アイテムID。鉱物は1000 + 色コード（希少度、スタック上限、採掘時間）
game/              レイキャスト、物理演算、インベントリ、採掘、建築、霧、色、食事、ステータス、
                   進行（レベル、経験値、敵レベル）、戦闘（イベント）、表示（タイプライター）、
                   スプライト（ピクセルスライム）、エンカウント、死亡、昼夜、
                   村（状態機械によるコマンド画面）、村データ（各村の提供内容）
audio/sfx.py       プログラムによる効果音生成 → assets/sfx/*.wav（初回起動時に生成）
audio/music.py     BGMを作曲・レンダリング。audio/director.pyが再生を維持し、新しい曲を作る
```

## 調整項目

- 採掘時間：`blocks.py` の `hardness`。採掘音の間隔：`config.HIT_INTERVAL`。
- 地形、湖、洞窟、木：`config.py` の `TERRAIN_*`、`CAVE_THRESHOLD`、`TREE_CHANCE`。
- 描画距離：`config.RENDER_RADIUS`（チャンク単位）。

## このバージョンの既知の制限

- 戦闘画面では、Ursina の `Button`、`Entity(origin=...)` を使ったバー、`Entity.scale_x` を使用している。初回起動時にバーやボタンの表示がおかしい場合は、`main.py` の「battle screen」部分を確認する。
- スプライトはテクスチャの透過に依存している。透明ピクセルは黒く描画されるため、透過が無効でも黒い戦闘画面では見えない。
- 夜間の暗転には `scene.setColorScale` を使用する。夜にワールドが暗くならない場合は `apply_fog()` を確認する。
- 実際のUrsinaをインストールせずに開発・テストされた。エンジンに依存しないロジックはテスト済みだが、`main.py` 内のUrsina呼び出しはテストされていない。初回起動で問題が起きた場合は、まず以下を確認する。
  1. 遠景の地形が霧で薄くならない：`on_mesh()` で `e.shader = None` を設定し、シーンの霧が適用されるようにする。
  2. 地形の色が表示されない：`Mesh(colors=...)` の頂点カラーを確認する。
  3. 音が出ない：`Audio(name)` がプロジェクトフォルダ内からWAVファイルを探しているか確認する。
  4. ひび割れのオーバーレイが見えない：`make_crack_textures()` を確認する。Pillowが必要で、利用できない場合は暗いオーバーレイにフォールバックする。

保存される追加情報：レベル、経験値、4つの能力値、HP、色、インベントリ、時刻、村の倉庫と進行状況、宿屋の復活地点、ボス撃破済みかどうか、案内人からボスの居場所を教えてもらったかどうか。

ブロックのメッシュは、水や葉も含めてすべて不透明である。
